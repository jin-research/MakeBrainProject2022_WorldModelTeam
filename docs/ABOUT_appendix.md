### TensorFlow、Docker、PyTorch

PC の環境構築は TensorFlow から始めました。ライブラリ、CUDA、GPU ドライバの依存関係を解消できませんでした。

次に Docker を試しました。Docker 自体は導入できました。私たちが必要とするイメージは用意されておらず、イメージを自作する段階で Docker の使用を止めました。

その後、フレームワークを TensorFlow から PyTorch へ変更しました。Ubuntu を 22.04 から 20.04 へ入れ直し、pyenv で仮想環境を作り、Jupyter Notebook を導入しました。CUDA Toolkit も 11.5 から 11.1 へ下がっています。

この順序は、TensorFlow → Docker → PyTorch でした。

#### PC と Jetson のどちらに合わせるか

環境をどちらに寄せるかは、当時こう考えていました。記録から引きます。

> 要するに、jetpackの方にPCを合わせる
> → これではこれまでのやってきて無理だった内容と変わらない
> → pythonはjetpackに入っているために3.6.9ということでこちらでfileを編集して色々やるのは無理。
> → ということで、こっちの方でdockerfileなどを作って、入れてしまってからjetsonに合わせてもらう方向に

**Jetson の Python は JetPack に同梱されていて動かせない**、という制約が出発点でした。だから PC を Jetson に合わせるのではなく、PC 側でイメージを作ってから Jetson に持っていく、という方針を採っています。

この判断が、後の作業の形を決めました。PC と Jetson は別々の環境として扱い、あいだを重みのファイルだけでつなぐ、という構成になっています。

Docker を検討したときは、NVIDIA の `l4t-pytorch:r32.6.1-pth1.9-py3`（PyTorch 1.9.0 / torchvision 0.10.0 / torchaudio 0.9.0）も候補に挙がっていました。

### Jetson の呼び名

| 機体 | JetPack | 記録 |
|---|---|---|
| Nao | 4.2.2 | 最終的に走行した実機。XiaoR ベンダ版 Donkey Car と stock PyTorch 1.1.0 |
| Jassy | 4.6.2 | PCA9685 経路と、自前ビルドした cp37 PyTorch 1.9.0 |
| Chaos | 4.6.1 | Nao を Jassy の JetPack 版へ合わせて焼き直した状態の呼び名 |

私たちは当時、Jassy と Nao を中心に整理しました。**Chaos は3台目の機体ではありません**。当時の記録に「nao の jetpack バージョンを jassy の方に合わせるように新たにフラッシュしたもの」（2022-11-22）とあります。この試みは「保留」のまま終わり、最終的に走行したのは JetPack 4.2.2 の Nao です。

### 環境構築とハードウェアに使った期間

私たちは、世界モデルを用いた機械学習以外の箇所に約8か月を使いました。ハードウェア対応には約5か月を使いました。

この期間には、PC のフレームワークと依存環境、シミュレータ、Jetson Nano の aarch64 環境、改造 JetPack、拡張ボード、カメラ、モーター、重みの受け渡しが含まれます。

この記録は学習1回の所要時間ではありません。8か月は環境構築とハードウェア対応の期間で、学習1回の時間ではありません。
