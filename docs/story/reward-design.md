# 報酬設計の4版 — CTEを捨てて、色で走る

2022年10月21日〜10月31日

## 問題

Donkey Car のシミュレータが標準で使う報酬は、コース中心からの距離（CTE）で計算します。実環境には CTE がありません。実機で走らせるには、カメラ画像だけから計算できる報酬が必要でした。

## 対応

CTE を使う報酬と終了条件を捨て、指定色（路面の線の色）の画素割合を使う処理へ変えました。この10日間に4版が残っています。

| ファイル | 更新日時 | 位置づけ |
|---|---|---|
| `donkey_sim_original.py` | 2022-10-21 19:53 | 改変前の基準 |
| `donkey_sim_archive_reward_1021.py` | 2022-10-22 00:58 | 報酬を書き換えた最初の版 |
| `donkey_sim_.py` | 2022-10-26 19:21 | 中間版 |
| `donkey_sim.py` | 2022-10-31 19:32 | 最終版 |

報酬の基準値 `base_all_square_pixel_percentage` は2、10、5の順に調整しました。終了カウンタは `15*10` から `15*2` へ変更しました。

## 色の範囲の決め方

最終的な基準は R:210–240、G:170–200、B:110–140 でした。これはシミュレータの路面色 `#ECBC79` を囲む範囲です。実環境のテープからも `#eaa004` と `#fccc54` のサンプルを取りましたが、どちらもこの範囲には入らず、「結構違うので別々にする」と判断しました。実機側では範囲を上下へ10広げていますが、なぜ10なのかの理由は記録に残っていません。
